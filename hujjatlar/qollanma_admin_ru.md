# «Физика 10–11» — руководство администратора

Администратор управляет платформой: пользователи, школы, модерация контента, переводы, статистика и безопасность.
Техническая установка: [`backend/README.md`](../backend/README.md).

---

## 1. Вход в панель администратора

Адрес: `https://<сайт>/admin/`. В production вход **двухэтапный**: логин + пароль + **6-значный код**
(Google Authenticator, Microsoft Authenticator или другое TOTP-приложение).

Первичная настройка (выполняет администратор сервера):
```bash
python manage.py createsuperuser
python manage.py admin_2fa_setup <логин>          # появится QR-код — отсканируйте в приложении
```
Если телефон потерян: `python manage.py admin_2fa_setup <логин> --reset` и отсканируйте заново.

После входа на **главной странице**: число учеников, учителей, школ, активных пользователей, график активности
за 30 дней, список **«Ожидает проверки»** (вопросы-черновики, разработки на модерации, неподтверждённые школы
и учителя — по клику открывается нужный список), регионы и последние действия.
Красные цифры в левом меню — количество записей, ожидающих проверки. В правом верхнем углу — светлая/тёмная тема.

> Никому не передавайте пароль администратора и телефон. Для каждого администратора создавайте отдельный аккаунт.

## 2. Пользователи

Раздел **«Пользователи»**: поиск (имя, телефон, логин), фильтр по роли (ученик / учитель / админ) и школе.

- **Учитель не подтверждён** (SMS не пришло) — отметку `is_verified` можно поставить вручную
  (после проверки личности по телефону).
- **Смена роли** записывается в журнал безопасности.
- **Запрос на удаление аккаунта** — пользователь подаёт сам; через 30 дней аккаунт удаляется автоматически
  (ежедневно ночью). Результаты тестов остаются в виде анонимной статистики.
- **История входов** — для каждого пользователя (IP, браузер, успешно/неуспешно).

## 3. Школы и классы

Школы распределены по 14 регионам; район при регистрации учителя выбирается из готового списка
(`apps/schools/districts.py`, если района нет — вписывается вручную). Если одна школа записана дважды
(например, «12-maktab» и «12-sonli maktab»), переведите учителей в одну, а вторую удалите.
Число **неподтверждённых школ** показывается в боковом меню красной цифрой.

Классы можно просматривать и архивировать. Классы завершившегося учебного года (например, «2025–2026»)
**автоматически архивируются каждую ночь начиная с 1 июля** — в журнале аудита остаётся запись
«Класс автоматически архивирован».

## 4. Модерация контента

### Вопросы
**Тесты → Вопросы**, фильтр «Статус: черновик». Проверьте вопрос учителя (текст, варианты, правильный ответ,
пояснение) → поставьте статус **«Одобрено»** — вопрос попадёт в общий банк.
В столбце статистики видно «% верных»: вопросы со слишком низким (< 15%) или слишком высоким (> 95%) процентом
стоит пересмотреть. Вопрос, использованный в задании, не удаляется — он **архивируется**.

Задачи: ответ, единица и допустимая погрешность (%). **Задача с параметрами**: `params` (например,
`{"m": [1, 5, 0.5]}` — от 1 до 5 с шагом 0,5) и `formula` (например, `m*9.8`); в тексте `{m}`.
Учителя могут добавлять такие задачи и сами — в панели учителя, с предпросмотром.

### Разработки уроков
**Контент → Разработки уроков**, фильтр «На модерации». Скачайте файл → **«Опубликовать»** или
**«Отклонить»** (комментарий обязателен — учитель увидит причину). Файлы автоматически проверяются при загрузке
(тип, размер; DOCX с макросами отклоняется).

### Переводы
**Контент → Переводы** — русские тексты сайта (интерфейс, вопросы тестов, задачи). Изменение появляется на сайте
автоматически (из-за кэша браузера — в течение 10 минут). Обновить резервный файл на сайте (для работы без
интернета) — по желанию: `python manage.py export_i18n`. Перевод, в тексте которого есть `{}`, — шаблон: вместо `{}`
подставляется число или имя; в переводе количество `{}` должно совпадать.

### Модели
В панели администратора у модели меняются название, описание, порядок, шаги задания, ожидаемые результаты; модель
можно сделать неактивной (она скроется из каталога). Чтобы добавить **новую модель**, программист должен создать
её страницу (`modellar/*_model.html`) — сама панель администратора новую симуляцию создать не может.

Если страницы моделей изменились (новая модель, столбцы журнала): `python manage.py import_simulations`. Старые
журналы остаются в старой версии схемы. **Внимание:** команда возвращает название, описание и шаги к тексту
страницы — изменения, сделанные в панели администратора, придётся внести заново (активность модели сохраняется).

### Где на сайте появляется то, что добавлено в панели администратора
| В панели администратора | На сайте | Когда |
|---|---|---|
| Вопрос или задача (статус «Одобрено») | Тренировочный тест, задания учителей | сразу |
| Название, описание, порядок, отметка «активна» модели | Каталог на главной странице | до 10 минут (кэш) |
| Шаги задания модели | Страница модели | до 10 минут |
| Ожидаемые результаты модели | Страница модели (только учителю) | сразу |
| Разработка урока (статус «Опубликовано», с PDF) | Страница «Разработки уроков» | сразу |
| Школа | Форма регистрации учителя | сразу |
| Уведомление | Список 🔔 пользователя | сразу |
| Русский перевод | Все страницы (русский режим) | до 10 минут |
| Пользователь, класс, задание | Панель соответствующего пользователя | сразу |

Всё это проверяется автоматическим тестом: `backend/e2e/admin_to_site.js` (на тестовом сервере).

## 5. Статистика

**Главная страница** панели администратора: ученики, учителя, школы, активные классы, активные за 7/30 дней,
лабораторные журналы, завершённые тесты, задания; график активности за 30 дней; пользователи по регионам;
самые используемые модели; последние действия аудита. Те же данные через API:
`GET /api/v1/analytics/platform/` (под аккаунтом администратора).

## 6. Журнал безопасности (аудит)

**Аудит → Журнал**: входы, смена пароля, удаление аккаунта, смена роли, выставление/изменение оценки
(прежнее и новое значение), возврат работ, удаления, модерация, автоархивация классов. В каждой записи — кто,
когда, IP.

Журнал **нельзя редактировать или удалять** (даже администратору). Записи старше 1 года автоматически
удаляются еженедельно.

При жалобе («кто-то изменил оценку») отфильтруйте по объекту и посмотрите, кто её изменил.

## 7. Работа сервера (для технического администратора)

| Задача | Как |
|---|---|
| Проверка состояния | `GET /api/v1/health/` → `{"status":"ok"}` (база и кэш) |
| Резервная копия | каждую ночь `scripts/backup.sh` (cron), хранится 30 дней |
| Восстановление | `scripts/restore.sh <файл.dump>`; раз в месяц проверяйте восстановление на тестовой базе |
| Ошибки | Sentry (`SENTRY_DSN`), логи gunicorn: `docker compose logs api` |
| Обновление | `git pull` → `docker compose up -d --build` → `docker compose exec api python manage.py migrate` |
| Фоновые задачи | контейнеры `celery` и `beat`: email, напоминания о сроках, удаление аккаунтов, очистка аудита, автоархивация классов |

**Важно:** сервер и резервные копии должны находиться **на территории Узбекистана** (ЗРУ-547, статья 27¹).

## 8. Неполадки

| Признак | Причина и решение |
|---|---|
| Учителям не приходят SMS | Проверьте `SMS_PROVIDER=eskiz`, `SMS_API_TOKEN` и баланс Eskiz.uz |
| Не приходит email | Настройки `EMAIL_HOST*`; работает ли контейнер `celery` |
| Не приходят напоминания о сроках | Работает ли контейнер `beat` |
| На сайте нет кнопки «Войти» | API не работает: откройте `/api/v1/health/` |
| Админка не принимает код | Неверное время на телефоне (включите автоматическое время) или `admin_2fa_setup --reset` |
| Изменение в панели не видно на сайте | Подождите до 10 минут (кэш) или обновите страницу с очисткой кэша (Ctrl+F5) |
